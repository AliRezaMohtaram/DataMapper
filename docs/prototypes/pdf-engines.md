# مقایسهٔ موتورهای PDF برای گزارش‌ساز

نمونهٔ آزمایشی: `prototypes/ReportPdf`. هر دو PDF همین پوشه (`report-chromium-150.pdf`, `report-questpdf-150.pdf`) از یک
داده ساخته شده‌اند: ۱۵۰ ردیف هزینه، گروه‌بندی بر اساس مرکز هزینه، جمع جزء و کل، سرستون تکراری، شمارهٔ صفحه، تاریخ شمسی،
رقم فارسی، متن مخلوط فارسی/انگلیسی (ISO 9001:2015، Atlas Copco GA-37) و بلوک امضا.

| | Chromium (HTML → PDF) | QuestPDF |
|---|---|---|
| کیفیت متن فارسی، نیم‌فاصله، ی/ک، متن مخلوط | عالی | عالی (با چشم تفاوتی دیده نشد) |
| ۱۵۰ ردیف (۶ صفحه) | ۱٫۴ ثانیه (اولین اجرا با بالا آمدن مرورگر ۴٫۷) | ۰٫۴ ثانیه |
| ۳۰۰۰ ردیف | ۹٫۴ ثانیه، ۹۲ صفحه | ۲٫۰ ثانیه، ۱۲۷ صفحه* |
| پیش‌نمایش در مرورگر | همان HTML؛ پیش‌نمایش و چاپ مستقیم یکسان‌اند | پیش‌نمایش باید جدا ساخته شود (HTML یا تصویر صفحه‌ها) |
| سرصفحه/پاصفحه و «صفحه X از Y» | دارد؛ ولی فونت باید روی سرور نصب باشد (قالب سرصفحه فونت وب نمی‌گیرد) | دارد؛ کنترل کامل در کد |
| صفحه‌بندی (شکستن جدول، تکرار سرستون، جدا نشدن ردیف) | با CSS؛ کافی ولی کنترل کمتر | دقیق‌تر و قابل‌کنترل‌تر |
| استقرار | Chromium روی سرور (حدود ۲۰۰ مگابایت، یا Edge/Chrome نصب‌شده) | فقط یک پکیج NuGet |
| مجوز | رایگان | رایگان برای سازمان با درآمد سالانه زیر ۱ میلیون دلار؛ بالاتر پولی |

\* تفاوت تعداد صفحه از چیدمان نمونه است، نه موتور: در نسخهٔ QuestPDF عنوان گزارش در بالای همهٔ صفحه‌ها تکرار می‌شود.

جمع‌بندی: از نظر کیفیت فارسی هر دو قابل‌قبول‌اند. QuestPDF حدود ۴ تا ۵ برابر سریع‌تر و استقرارش ساده‌تر است؛ Chromium مزیت
«یک چیدمان برای پیش‌نمایش، چاپ و PDF» دارد ولی به مرورگر و نصب فونت روی سرور نیاز دارد.

## با محدودیت‌های سرور (بدون نصب برنامه، بدون وابستگی تجاری، بدون اینترنت)

- **Chromium روی سرور:** کنار گذاشته شد (نیاز به نصب مرورگر و فونت روی سرور).
- **QuestPDF فعلی:** نصب و اینترنت لازم ندارد (همه‌چیز داخل پکیج است)، ولی مجوزش برای سازمان‌های بزرگ‌تر تجاری است.
- **QuestPDF 2022.12.15 (آخرین نسخهٔ MIT):** آزمایش شد (`questpdf-2022-mit-persian.png`): حروف فارسی درست می‌چسبند ولی
  ترتیب راست‌به‌چپ متن مخلوط خراب است (ISO → OSI، ۱۲ → ۲۱، مبلغ‌ها به‌هم‌ریخته). قابل استفاده نیست.
- **PdfSharp/MigraDoc (MIT):** شکل‌دهی حروف عربی/فارسی و راست‌به‌چپ ندارد.
- **iText:** مجوز AGPL یا تجاری، و راست‌به‌چپ در افزونهٔ تجاری است.

**گزینهٔ پیشنهادی: چاپ در مرورگر کاربر.** سرور فقط HTML گزارش را می‌سازد؛ کاربر «چاپ → ذخیره به‌صورت PDF» می‌زند.
سرصفحه، پاصفحه و «صفحهٔ ۲ از ۶» با رقم فارسی از CSS (`@page` margin boxes و `counter(page, persian)`) می‌آیند و فونت
همان فونت وب صفحه است — هیچ نصبی روی سرور یا کلاینت لازم نیست. آزمایش شد بدون هیچ فونت نصب‌شده:
`report-browser-print-150.pdf`. نیاز: Chrome یا Edge نسخهٔ ۱۳۱ به بالا (Firefox سرصفحه/شمارهٔ صفحه را نشان نمی‌دهد).
محدودیت: PDF روی سرور ساخته نمی‌شود (برای ارسال زمان‌بندی‌شده یا بایگانی خودکار).

**اگر بعداً PDF سمت سرور لازم شد:** موتور اختصاصی روی SkiaSharp + HarfBuzzSharp (هر دو MIT؛ کتابخانه‌های بومی داخل پکیج
NuGet هستند و فقط کنار برنامه کپی می‌شوند، نصب لازم ندارند). شکل‌دهی حروف را HarfBuzz انجام می‌دهد؛ الگوریتم راست‌به‌چپ
(Unicode BiDi) و صفحه‌بندی باندها را خودمان می‌نویسیم — کار قابل‌توجه ولی شدنی، چون چیدمان باندیِ گزارش‌ساز را به‌هرحال
خودمان محاسبه می‌کنیم.
