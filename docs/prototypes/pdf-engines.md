# مقایسهٔ موتورهای PDF برای گزارش‌ساز

نمونهٔ آزمایشی: `prototypes/ReportPdf`. هر دو PDF همین پوشه (`report-chromium-150.pdf`, `report-questpdf-150.pdf`) از یک
داده ساخته شده‌اند: ۱۵۰ ردیف هزینه، گروه‌بندی بر اساس مرکز هزینه، جمع جزء و کل، سرستون تکراری، شمارهٔ صفحه، تاریخ شمسی،
رقم فارسی، متن مخلوط فارسی/انگلیسی (ISO 9001:2015، Atlas Copco GA-37) و بلوک امضا.

| | Chromium (HTML → PDF) | QuestPDF |
|---|---|---|
| کیفیت متن فارسی، نیم‌فاصله، ی/ک، متن مخلوط | عالی | عالی (با چشم تفاوتی دیده نشد) |
| ۱۵۰ ردیف (۶ صفحه) | ۱٫۴ ثانیه (اولین اجرا با بالا آمدن مرورگر ۴٫۷) | ۰٫۴ ثانیه |
| ۳۰۰۰ ردیف | ۹٫۴ ثانیه، ۹۲ صفحه | ۲٫۰ ثانیه، ۱۲۷ صفحه* |
| پیش‌نمایش در مرورگر | همان HTML؛ پیش‌نمایش و چاپ مستقیم یکسان‌اند | پیش‌نمایش باید جدا ساخته شود (HTML یا تصویر صفحه‌ها) |
| سرصفحه/پاصفحه و «صفحه X از Y» | دارد؛ ولی فونت باید روی سرور نصب باشد (قالب سرصفحه فونت وب نمی‌گیرد) | دارد؛ کنترل کامل در کد |
| صفحه‌بندی (شکستن جدول، تکرار سرستون، جدا نشدن ردیف) | با CSS؛ کافی ولی کنترل کمتر | دقیق‌تر و قابل‌کنترل‌تر |
| استقرار | Chromium روی سرور (حدود ۲۰۰ مگابایت، یا Edge/Chrome نصب‌شده) | فقط یک پکیج NuGet |
| مجوز | رایگان | رایگان برای سازمان با درآمد سالانه زیر ۱ میلیون دلار؛ بالاتر پولی |

\* تفاوت تعداد صفحه از چیدمان نمونه است، نه موتور: در نسخهٔ QuestPDF عنوان گزارش در بالای همهٔ صفحه‌ها تکرار می‌شود.

جمع‌بندی: از نظر کیفیت فارسی هر دو قابل‌قبول‌اند. QuestPDF حدود ۴ تا ۵ برابر سریع‌تر و استقرارش ساده‌تر است؛ Chromium مزیت
«یک چیدمان برای پیش‌نمایش، چاپ و PDF» دارد ولی به مرورگر و نصب فونت روی سرور نیاز دارد.
