# چک‌لیست تست دستی: ورود و کاربران

پیش‌نیاز: اجرای Mapper در Development. جدول‌های `usr` خودکار ساخته می‌شوند و کاربر `admin` با رمز `Admin@12345`
(در `appsettings.Development.json`) ساخته می‌شود.

- [ ] ۱. باز کردن هر صفحه بدون ورود ← انتقال به صفحهٔ ورود؛ بعد از ورود، برگشت به همان صفحه.
- [ ] ۲. ظاهر صفحهٔ ورود در حالت تیره و روشن و در عرض موبایل (بدون منوی کناری).
- [ ] ۳. ورود با `admin` و رمز اشتباه ← پیام خطا؛ با رمز درست ← میز کار.
- [ ] ۴. در منوی پایین سمت کناری: نام «مدیر سامانه»، «تغییر رمز عبور» (مودال) و «خروج».
- [ ] ۵. منوی «سیستم ← کاربران» فقط برای مدیر دیده شود؛ فهرست، جستجو و فیلتر فعال/غیرفعال.
- [ ] ۶. «کاربر جدید» (مودال): نام کاربری تکراری، رمز کوتاه یا بدون رقم، و تکرار نادرست رمز ← خطا داخل همان فرم.
- [ ] ۷. ورود کاربر جدید با ایمیل به‌جای نام کاربری.
- [ ] ۸. کاربر عادی آدرس `/Users` را باز کند ← صفحهٔ «دسترسی ندارید».
- [ ] ۹. غیرفعال‌سازی کاربری که در مرورگر دیگری وارد شده ← حداکثر یک دقیقه بعد به صفحهٔ ورود برود و دیگر نتواند وارد شود.
- [ ] ۱۰. پنج بار رمز اشتباه ← «قفل موقت» در فهرست؛ «تعیین رمز جدید» قفل را بردارد.
- [ ] ۱۱. مدیر نتواند خودش را غیرفعال کند یا دسترسی مدیریتی خودش را بردارد.
- [ ] ۱۲. ساخت یا ویرایش یک رکورد در Mapper (مثلاً منبع داده) ← ستون `CreatedBy`/`UpdatedBy` در جدول، شناسهٔ کاربر واردشده باشد.
